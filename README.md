# localstack-nango-demo

A sample app that runs a full [Nango](https://www.nango.dev/) integration loop
against [LocalStack application emulators](https://www.localstack.cloud/), so you
can develop and test third-party integrations (Stripe, Xero, HubSpot, ...)
without touching a single real SaaS account or leaving your machine.

## What this shows

- A self-hosted Nango server, its Postgres and Redis, all in Docker.
- Three pre-built Nango integrations from https://nango.dev/api-integrations:
  Stripe, Xero and HubSpot.
- Nango's proxy and syncs pointed at LocalStack's app emulators instead of the
  real APIs, using a per-request `Base-Url-Override`.
- A local dev loop (`make up` -> `make bootstrap` -> `make seed` -> `make test`)
  that also runs unchanged in CI.

## Architecture

```
  ┌─────────────┐   nango deploy            ┌──────────────────────────┐
  │  Nango CLI  │ ───────────────────────▶  │   Nango server           │
  └─────────────┘   nango.yaml + syncs      │   (self-hosted, Docker)  │
                                            │   localhost:3003         │
  ┌─────────────┐   POST /proxy/...         │                          │
  │ demo / CI   │ ───────────────────────▶  │   proxy + sync engine    │
  │   tests     │ ◀───────────────────────  │                          │
  └─────────────┘   records / responses     └───────────┬──────────────┘
                                                        │ Base-Url-Override
                                                        ▼
                            ┌───────────────────────────────────────────┐
                            │   LocalStack app emulators   :4566        │
                            │   stripe.  |  xero.  |  hubspot.          │
                            │        localhost.localstack.cloud         │
                            └───────────────────────────────────────────┘
```

The LocalStack container is given compose network aliases
(`stripe.localhost.localstack.cloud`, ...), so the Nango proxy container reaches
the emulators with the `Host` header they route on. On the host machine the same
names resolve to `127.0.0.1` via public DNS.

## Prerequisites

- Docker and Docker Compose v2
- Node.js 20+
- A LocalStack auth token with the app emulators feature
  (https://app.localstack.cloud). App emulators are a LocalStack Pro capability.

## Quickstart

```bash
cp .env.example .env
# edit .env: set LOCALSTACK_AUTH_TOKEN, and NANGO_ENCRYPTION_KEY (openssl rand -base64 32)

make up          # start LocalStack + Nango (server, db, redis)
make deploy      # push nango.yaml + syncs to the local Nango server
make bootstrap   # register the 3 integrations and a demo connection each
make seed        # create sample data inside the Stripe/Xero/HubSpot emulators
make demo        # read that data back through the Nango proxy
make test        # run the local dev-loop test suite
make down        # stop everything
```

`make` on its own prints every target with a description.

## Integrations

| Provider config key | Nango provider   | Emulator base URL                               | Demo data      |
| ------------------- | ---------------- | ---------------------------------------------- | -------------- |
| `stripe`            | `stripe`         | `http://stripe.localhost.localstack.cloud:4566`  | customers      |
| `xero`              | `xero`           | `http://xero.localhost.localstack.cloud:4566`    | invoices       |
| `hubspot`           | `hubspot`        | `http://hubspot.localhost.localstack.cloud:4566` | contacts       |

## Project layout

```
docker-compose.yml            LocalStack + Nango stack
Makefile                      self-describing entrypoint for every task
.env.example                  required configuration
nango-integrations/
  nango.yaml                  integration + sync definitions
  models.ts                   generated model types (regenerated by `nango deploy`)
  stripe/syncs/               Stripe customer sync
  xero/syncs/                 Xero invoice sync
  hubspot/syncs/              HubSpot contact sync
scripts/
  lib.sh                      shared shell helpers
  bootstrap.sh                register integrations + connections via the Nango API
  seed-emulators.sh           create sample records in the emulators
  demo.sh                     read records back through the Nango proxy
tests/
  integration.test.mjs        end-to-end local dev-loop checks
.github/workflows/ci.yml      the same loop, in CI
```

## CI

`.github/workflows/ci.yml` runs the identical loop on every push and PR. It
needs one repository secret:

- `LOCALSTACK_AUTH_TOKEN` (required, app emulators are Pro)
- `NANGO_ENCRYPTION_KEY` (optional, a throwaway key is used if unset)

## Troubleshooting

- **`make up` fails on LocalStack**: check `LOCALSTACK_AUTH_TOKEN` and that your
  plan includes app emulators. `make logs` tails both stacks.
- **Proxy calls return connection errors**: the emulator hostnames must resolve
  to the LocalStack container from inside the Nango container. Confirm the
  network aliases in `docker-compose.yml` and that all services share one
  network.
- **Nango proxy rejects the override target**: Nango's proxy has an SSRF guard.
  `NANGO_PROXY_ALLOW_PRIVATE_TARGETS=true` in `docker-compose.yml` opts into
  private hosts for local development. Do not use that setting in production.
